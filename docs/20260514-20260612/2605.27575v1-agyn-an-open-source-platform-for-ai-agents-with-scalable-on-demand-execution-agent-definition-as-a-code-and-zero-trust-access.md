## 摘要
随着组织向AI智能体的生产部署迈进——这些智能体执行非确定性工作流、维护有状态会话，并且通常以特权访问内部服务——工程挑战从构建单个智能体转变为在适当的隔离、治理和安全性下大规模运维它们。本文介绍Agyn，一个围绕专为智能体工作负载设计的三个关键原则构建的开源平台：基于Kubernetes的信号驱动、有状态无服务器运行时；用于智能体和工具定义的Terraform提供商；以及基于零信任和最小权限原则的安全模型。Agyn是智能体无关、模型无关和云无关的。

## Abstract
As organizations move toward production deployments of AI agents, which execute non-deterministic workflows, maintain stateful sessions, and often operate with privileged access to internal services, the engineering challenge shifts from building individual agents to operating them at scale with proper isolation, governance, and security. In this paper we present Agyn, an open-source platform designed around three key principles tailored for agent workloads: a signal-driven, stateful serverless runtime on Kubernetes; a Terraform provider for agent and harness definition; and a security model grounded in zero-trust and least-privilege principles. Agyn is agent-agnostic, model-agnostic, and cloud-agnostic.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **核心问题**：随着AI智能体从原型走向生产部署，组织面临的挑战从“构建单个智能体”转变为“在适当的隔离、治理和安全性下，大规模可靠地运维大量智能体”。现有基础设施无法同时满足以下三个关键需求：
  1. **高效的按需执行**：无法为每个智能体定义预先保留专用计算资源（会导致大量空闲浪费），必须按需分配并立即回收空闲资源。
  2. **智能体定义即代码（Agent Definition as Code）**：智能体的配置（提示词、工具、密钥、资源限制）应像基础设施代码一样进行版本控制、代码审查和可重复部署。
  3. **零信任访问内部服务**：访问必须基于身份、默认拒绝、最小权限，绝不能让AI模型能直接接触凭证。平台不能因为智能体运行在企业网络内就信任它，每个请求都必须单独授权。

- **整体含义**：现有系统仅能部分满足这些需求：无服务器平台（如Knative, AWS Lambda）缺乏对状态对话和智能体触发的原生支持；基础设施即代码（IaC）框架缺乏面向智能体的抽象；零信任网络需要的手动身份管理与临时执行不匹配。因此，需要一个集成的解决方案，本文提出的**Agyn**开源平台正是为此而生。它是智能体无关、模型无关、云无关的。

## 2. 论文提出的方法论：核心思想、关键技术细节

- **核心思想**：围绕三个关键原则设计一个平台：信号驱动的有状态无服务器运行时、通过Terraform将智能体及其配套基础设施作为代码管理、基于零信任和最小权限的安全模型。

- **关键技术细节**（按架构三部分展开）：
  1. **运行时：信号驱动的有状态无服务器智能体**
     - **信号驱动生成**：当用户在线程（Thread）中发送消息时，通知服务发布事件，代理编排器（Agents Orchestrator）订阅事件，解析智能体密钥，请求OpenZiti身份，并指令k8s-runner创建一个Kubernetes Pod。Pod挂载持久卷（保留之前的会话状态），使智能体能从上次中断处继续执行。
     - **空闲回收**：活跃时每10秒发送心跳；空闲超时（默认5分钟）后，编排器停止Pod并删除网络身份。持久卷和线程历史保留；下一条消息会生成一个新Pod并重新挂载相同状态。
  2. **配置：智能体和工具框架作为代码（Agents and Harnesses as Code）**
     - 通过一个**Terraform提供者（Provider）** 完整声明智能体定义及其配套基础设施（即“工具框架”harness）：包括智能体容器、工作区配置、系统提示、模型、密钥、MCP服务器、持久卷等。
     - 平台提供三个预构建智能体镜像（Claude Code, OpenAI Codex, Agyn自己的agent-loop实现），组织也可自带容器。
     - Terraform的模块结构允许组织将公共工具框架模式打包为可复用模块，确保一致性和避免重复。运行`terraform apply`后，定义通过Gateway解析到智能体服务，后续消息按最新定义派生Pod，无需重启。
  3. **安全：零信任与最小权限**
     - **每容器隔离**：每个智能体Pod的主容器运行智能体进程，边车（sidecar）容器运行MCP服务器。文件系统和进程树独立，仅共享回环接口。密钥仅注入需要它的容器（通常是MCP边车），从不注入驱动LLM的智能体容器。
     - **零信任覆盖网络**：通过**OpenZiti**实现。每个智能体在生成时获得一个临时x509证书，在mTLS握手时建立身份。Gateway提取身份并传递给下游服务，因此每个下游服务都知道是哪个智能体在请求。基于属性的访问控制（ABAC）策略限制每个智能体只能访问其明确需要的服务。
     - **基于关系的授权（ReBAC）**：使用**OpenFGA**（受Zanzibar启发）通过图遍历强制执行细粒度权限。按角色（拥有者、维护者、参与者）限定谁能配置或与智能体交互；线程访问限定为参与者。

## 7. 优点

- **设计理念清晰、系统性强**：将无服务器、基础设施即代码、零信任三个成熟领域原则针对智能体工作负载有机融合，而非简单拼凑。
- **智能体无关、模型无关、云无关**：支持多种LLM（通过API或自定义容器）、多种智能体框架（LangGraph, AutoGen等），可部署在任何Kubernetes集群上（包括本地），避免供应商锁定。
- **安全架构深入**：实施每容器隔离（即使MCP被攻破也不影响智能体进程）、临时身份（每次生成新Pod），以及基于回环接口限制通信，防止凭证泄露；利用OpenZiti提供传输层安全，无需暴露集群内部网络。
- **采用行业标准工具**（Terraform、Kubernetes、OpenZiti、OpenFGA），降低组织采用门槛，便于集成现有基础设施。
- **开源许可证**（AGPL-3.0）鼓励社区贡献，有利于生态发展。
