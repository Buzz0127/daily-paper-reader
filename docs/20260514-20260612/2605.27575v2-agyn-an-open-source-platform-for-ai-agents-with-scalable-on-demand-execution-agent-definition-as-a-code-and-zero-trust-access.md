## 摘要
随着组织将AI代理投入生产部署，这些代理执行非确定性工作流、维护有状态会话，并通常拥有对内部服务的特权访问，工程挑战从构建单个代理转向在适当的隔离、治理和安全性下大规模运行它们。本文介绍了Agyn，这是一个开源平台，围绕代理工作负载的三个关键原则设计：Kubernetes上信号驱动的有状态无服务器运行时；用于代理和工具（harness）定义的Terraform提供者；以及基于零信任和最小权限原则的安全模型。Agyn是代理无关、模型无关和云无关的。

## Abstract
As organizations move toward production deployments of AI agents, which execute non-deterministic workflows, maintain stateful sessions, and often operate with privileged access to internal services, the engineering challenge shifts from building individual agents to operating them at scale with proper isolation, governance, and security. In this paper we present Agyn, an open-source platform designed around three key principles tailored for agent workloads: a signal-driven, stateful serverless runtime on Kubernetes; a Terraform provider for agent and harness definition; and a security model grounded in zero-trust and least-privilege principles. Agyn is agent-agnostic, model-agnostic, and cloud-agnostic.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **核心问题**：随着AI代理从原型走向生产部署，组织面临三大关键需求，现有基础设施无法同时满足：
  1. **高效按需执行**：代理实例需要时启动、空闲时回收，避免预分配导致的资源浪费。
  2. **代理定义即代码**：代理的提示词、工具、密钥等运营决策应受版本控制、可审查可回滚，如同基础设施代码。
  3. **零信任访问内部服务**：每个代理必须基于身份进行细粒度授权，即使模型被攻破也不能泄露凭据或越权。
- **研究动机**：现有系统（如Knative、AWS Lambda、HashiCorp Terraform、零信任网络等）只部分覆盖上述需求，缺乏集成方案。需要构建一个专为代理工作负载设计的平台，兼顾弹性、可治理性和安全性。
- **整体含义**：Agyn是一个开源、代理无关、模型无关、云无关的平台，通过将基础设施即代码和零信任安全原则引入代理生命周期管理，降低大规模运维复杂度。

## 2. 论文提出的方法论：核心思想、关键技术细节

### 核心思想
- **三层设计**：运行时层（信号驱动的有状态无服务器）、配置层（代理定义即代码，通过Terraform）、安全层（零信任+最小权限）。
- **关键模式**：每个代理定义可复用，每个执行实例绑定单个用户和单个任务（线程），实例是短暂的、由信号触发、有状态持久化。

### 关键技术细节

#### 运行时：信号驱动的有状态无服务器
- **信号驱动启动**：用户在线上发消息 → 通知服务发布事件 → 编排器协调 → 解析代理定义、解析密钥、请求OpenZiti身份 → 创建Kubernetes Pod。Pod挂载持久卷（恢复之前的工作空间状态），接收线程上下文，实现断点续传。
- **空闲回收**：活跃代理每10秒发送心跳，默认空闲超时5分钟后，编排器停止Pod并删除网络身份，但持久卷和线程历史保留，下次消息重新启动新实例并恢复状态。
- **对比FaaS**：传统FaaS针对HTTP短任务，而代理工作负载是会话式、多分钟级、有状态。Agyn结合了FaaS的弹性与有状态持久化。

#### 配置：代理和工具即代码（Terraform Provider）
- 通过自定义Terraform Provider声明代理完整定义：镜像、工作区配置、系统提示、模型、密钥、MCP服务器、持久卷等。
- 支持预构建代理镜像（Claude Code、OpenAI Codex、Agyn自实现），也支持自定义容器。
- 通过Terraform模块封装通用工具模式，实现复用和一致性。
- 每次`terraform apply`通过Gateway将定义写入Agents Service，后续消息自动使用新定义。

#### 安全：零信任与最小权限
- **每容器隔离**：每个Pod主进程运行代理，sidecar运行MCP服务器，各自独立文件系统和进程树，仅共享lo接口。密钥只注入到需要的容器（通常是MCP sidecar），代理容器从不接触密钥。
- **零信任覆盖网络**：使用OpenZiti，每个代理在启动时获得独立x509身份，mTLS握手时即确立身份，Gateway将身份传递至下游服务，实现ABAC策略。
- **关系型授权（ReBAC）**：基于OpenFGA（借鉴Zanzibar）配置代理角色（owner/maintainer/participant），控制谁可配置或交互代理，线程访问限于参与者。

### 算法/流程（文字说明）
- **核心流程**：消息到达 → 通知服务发布事件 → 编排器读取事件，查询线程关联的代理定义 → 解析并获取密钥 → 请求OpenZiti创建身份 → 通过k8s-runner创建Pod（带持久卷和身份） → 代理处理消息并回复。空闲后超时回收Pod和身份。
- **身份生命周期**：三种模式：临时每工作负载代理身份（启动时创建，停止时删除）、临时每Pod服务身份（自注册+租约）、持久身份（服务令牌预配置）。

## 6. 论文的主要结论与发现

- **主要结论**：Agyn是首个同时满足高效按需执行、代理定义即代码和零信任内部服务访问三大要求的开源平台。
- **关键发现**：通过将无服务器弹性、基础设施即代码和零信任安全原则有机整合，组织能够以与基础设施相同的治理水平运行AI代理，而无需在安全性或弹性上妥协。
- **独特贡献**：提出了“信号驱动的有状态无服务器”模式，解决代理会话式工作负载的启动/回收问题；通过Terraform provider实现代理定义与共享基础设施代码一致；通过OpenZiti和OpenFGA实现每个临时代理实例的细粒度最小权限。
- **局限性承认**：尚未实现每个暴露的Dial-policy范围控制、硬性支出上限、ReBAC覆盖扩展等，正在改进中。

## 7. 优点：方法或实验设计上的亮点

- **设计亮点**：
  - **状态保持的无服务器**：利用持久卷和线程ID实现冷启动后的断点续传，同时保留FaaS的弹性。
  - **代理定义即代码**：采用Terraform，可直接进行版本控制、代码审查、自动化部署，降低了运营成本。
  - **零信任原生集成**：每个实例临时身份、覆盖网络隔离、凭据永不进入模型容器，从根本上防止凭据泄露和越权。
  - **平台无关性**：代理、模型、云均无关，支持自托管，避免供应商锁定。
  - **MCP隔离**：sidecar架构保障MCP服务器与代理进程隔离，即使MCP被攻破也无法直接影响代理或其他MCP。
- **实现亮点**：
  - 使用Go开发平台服务，OpenZiti SDK嵌入基础设施服务（避免Istio sidecar冲突）。
  - 提供开箱即用的预构建代理镜像（Claude Code、Codex）和自定义容器支持。
  - 发布为Helm Chart，一键部署到任何Kubernetes集群。
