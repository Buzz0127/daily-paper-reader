## 摘要
跨会话持久化的AI智能体需要可检索、审计、更新和擦除的记忆。现有记忆系统常将源证据、提取事实、检索上下文和回答策略合并为一个不透明的提示路径，导致故障难以诊断：错误答案可能源于缺失证据、未支持提取、过时状态、检索丢失或回答模型行为。我们提出Eywa，一种围绕“先证据后信念”构建的基于溯源的记忆架构。Eywa在推导规范事实之前存储不可变的源证据，根据类型化信号和源支持验证提取的记忆，并通过确定性多路由读取路径（检索内部零LLM调用）检索有界记忆上下文。检索到的上下文与回答指令分开返回，使得同一记忆基座可跨前沿、预算和本地回答模型进行评估。在冻结的、工件记录的检索配置下，Eywa在LoCoMo C1-C4划分上结合Claude Sonnet 4.6写入和QA角色达到了90.19%的判断准确率。在LongMemEval-S上达到88.2%的检索充分性准确率。在BEAM（700个问题的技术记忆压力基准）上达到81.45%的平均nugget得分和85.29%的pass@score>=0.5。完整的每问题工件（包括问题、黄金答案、模型答案、检索上下文和标签）已发布于https://eywa.to/research。

## Abstract
AI agents that persist across sessions need memory they can retrieve, audit, update, and erase. Existing memory systems often collapse source evidence, extracted facts, retrieved context, and answer policy into one opaque prompt path, making failures difficult to diagnose: a wrong answer may come from missing evidence, unsupported extraction, stale state, retrieval loss, or answer-model behavior. We present Eywa, a provenance-grounded memory architecture built around evidence before belief. Eywa stores immutable source evidence before deriving canonical facts, validates extracted memories against typed signals and source support, and retrieves bounded memory context through a deterministic multi-route read path with zero LLM calls inside retrieval. Retrieved context is returned separately from answer instructions, allowing the same memory substrate to be evaluated across frontier, budget, and local answer models. Under a frozen, artifact-recorded retrieval configuration, Eywa reaches 90.19% judge accuracy on the LoCoMo C1-C4 split with Claude Sonnet 4.6 write and QA roles. On LongMemEval-S, it reaches 88.2% retrieval-sufficiency accuracy. On BEAM, a 700-question technical-memory stress benchmark, it reaches 81.45% mean nugget score and 85.29% pass@score >= 0.5. Full per-question artifacts, including questions, gold answers, model answers, retrieved context, and labels, are published at https://eywa.to/research.

## 1. 核心问题与整体含义（研究动机和背景）

- **核心问题**：AI 智能体需要跨会话持久化的记忆，但现有记忆系统（如 MemGPT、MemoryBank、Mem0 等）将源证据、提取的事实、检索上下文和答案策略混入同一个不透明的提示路径。当答案错误时，无法区分错误来自以下哪个环节：
  - 源对话未包含证据（覆盖缺口）
  - 提取的事实与源证据不一致（锚定缺口）
  - 事实过期或未被更新（修订缺口）
  - 检索未找到正确事实（检索缺口）
  - 答案模型收到了证据但拒绝使用/错误推理（合成缺口）
  - 评分指标本身不公平（测量缺口）
- **整体意义**：需要一种可审计、可诊断的长期记忆架构，使每个错误都能追溯到具体环节，从而实现系统性改进。同时，记忆应作为基础设施，而非提示装饰。

## 2. 方法论：核心思想、关键技术细节

### 核心思想
- **证据先于信念（evidence before belief）**：不可变的源证据（原始对话、时间戳、角色）是权威基座；提取的信念（事实、观察）是可修订的索引，且始终链接到支持它们的源证据。

### 关键技术细节

#### 记忆对象分层（不可混用）
| 对象 | 可变性 | 生产者 | 说明 |
|------|--------|--------|------|
| 证据（Evidence） | 不可变 | 对话摄取 | 原始文本+角色+时间+会话元数据 |
| 信号（Signals） | 追加式 | 确定性检测器 | 日期、实体、锚点等，无需 LLM |
| 候选事实（Candidates） | 临时 | 提取器 LLM | 验证前暂存 |
| 信念（Beliefs） | 可修订 | 验证器/写入器 | 持久化事实，带有生命周期和范围元数据 |
| 链接（Links） | 追加式 | 持久化层 | 溯源边，从信念指向证据 |

#### 写入路径（Write Path）
- **Tier 0（不可变捕获）**：将用户每次对话存储为不可变证据行，同时运行规则/正则 + spaCy NER 检测器提取类型化信号（日期、实体、版本、URL 等）——此过程零 LLM 调用。
- **Tier 1（验证提取）**：LLM 从证据窗口提取候选事实 `f̂`，并通过验证函数 `V` 检查：
  - `V_support`：与源文本的字面/模糊重叠
  - `V_hard`：硬锚（日期、数字等）与源信号完全匹配
  - `V_subject`：主题在支持窗口内
  - `V_act`：保留否定和不确定性
  - 验证通过的事实被写入，并携带指向证据行的溯源链接 `ℓ(f) → e`。失败候选被拒绝或标记修复。

#### 提取模式
- **规范型（Canonical）**：持久的个人档案事实，如偏好。
- **观察型（Observation）**：高召回的事件级事实，保留细节。
- **混合型（Hybrid）**：两者并行，推荐高召回场景。
- **结构化技术提取**：针对代码、版本、配置等技术细节。

#### 读取路径（Read Path）：零 LLM 确定性多路由
- **查询规划器（Query Planner）**：基于问题形状（精确、推理、计数、时间、布尔等）和实体/时间线索，分配通道权重，无需 LLM。
- **检索通道**：
  - `R_v`：向量检索（嵌入余弦）
  - `R_k`：关键词检索（BM25 + 查询扩展）
  - `R_t`：时间检索（根据事实有效期窗口过滤）
  - `R_g`：实体/图检索（从查询实体出发遍历知识图谱）
- **融合**：加权倒数排名融合（RRF）：`RRF(f) = Σ_c∈C w_c / (k + rank_c(f))`，默认 `k=20`。
- **后处理过滤器**：
  - **人员降权**：对非查询人员的事实乘以 0.05
  - **保留最低排名**：已匹配人员和时间窗口的候选事实不会掉出前 25 名
- **救援通道**：
  - 精确/列表/计数/间隔类问题激活原始段落救援（episode FTS 搜索，最多返回 6 条摘要事实）
  - 推理/因果类问题激活推理支持（检索该人员 120 个事实，按 0.7 余弦 + 0.3 词项重叠评分）
- **上下文打包**：按实体分组后按排名顺序，在预算 token 数内打包。

#### 答案策略分离
- **ReadResult** 包含两个分离字段：
  - `context`：打包的检索证据
  - `answer_instructions`：策略文本（严格/平衡/高级）
- 三种模式：
  - **strict**：仅从直接证据回答
  - **balanced**：允许强隐含
  - **advanced**：允许谨慎推理和平常知识桥接
- 这使得同一检索架构可服务不同能力/成本的答案模型。

## 6. 主要结论与发现

1. **高准确率**：Eywa 在 LoCoMo C1–C4 上达到 90.19% 判断准确率（Claude Sonnet 4.6），在 LongMemEval-S 上达到 88.2% 检索充分性，在 BEAM 上达到 81.45% 平均 nugget 分数和 85.29% pass@0.5。
2. **模型分离有效**：同一记忆存储可服务于不同能力的模型（前沿 API、预算模型、本地模型），且强写路径能提升弱 QA 模型的表现（如 Qwen3 32B 基于 Sonnet 记忆比自写记忆提升 10+ 百分点）。
3. **错误可定位**：诊断追踪显示 LongMemEval-S 剩余失败中最大来源为检索覆盖（27/59）、上下文选择丢失（12/59）、提取缺失（12/59）等，为后续改进指明了方向。
4. **零 LLM 读取可行**：确定性多路由检索达到 150–200 ms 延迟，且保持了高精度。
5. **拒绝感知评分揭示潜在高估**：LoCoMo 官方 token F1 可能因模型正确拒绝无法找到的答案而获得分数，拒绝对抗性问题时可能掩盖答案模型在推理类问题上的弱点。

## 7. 优点

- **溯源设计清晰**：从根本上区分证据与信念，使审计、修正、删除成为系统固有特性，而非事后补丁。
- **写读分离与零 LLM 读取**：写入时花费模型计算，读取时完全确定性，既降低延迟成本，又简化缓存和调试。
- **答案策略解耦**：允许同一记忆层在不同产品策略下复用（严格/平衡/高级），适应不同模型能力和安全要求。
- **公开逐问题工件**：每个基准问题的完整记录（问题、黄金答案/评分标准、检索上下文、模型输出、判断结果）公开发布，支持第三方审查和复现。
- **本地优先实现**：使用 SQLite、spaCy、ONNX Runtime 等本地组件，无需外部依赖，适合隐私敏感场景。
- **失败分类体系**：提出了全面的故障分类表（覆盖缺口、锚定缺口、修订缺口、范围缺口、时间缺口、检索缺口、合成缺口、测量缺口），为系统化诊断奠定基础。

## 8. 不足与局限

- **提取模型依赖**：结果强烈依赖于所选提取模型的能力；未进行针对多种本地提取器（如不同规模、不同供应商）的穷举扫描。
- **基准覆盖有限**：LoCoMo 仅 10 个对话，统计不确定性高；BEAM 为内部引入的基准，尚未经过独立社区验证。
- **缺乏消融与统计检验**：未提供路由消融、超参敏感性、置信区间等，报告的数字可能不够稳健。
- **手调超参**：所有路由权重、RRF 的 k、降权因子、保留排名深度均为手调值，未系统优化。

## 9. 未来工作

- **更丰富的提取与验证**：探索多模型投票、自一致性检查以及非易失性证据（如用户显式修正）的自动集成。
- **分布式与扩展性**：测试多进程、分布式部署下的写入吞吐、读取延迟和一致性保障。
- **自动超参优化**：对检索路由权重、RRF 的 k、降权因子等进行贝叶斯搜索，减少手动调参带来的偏差。
- **更广泛的模型覆盖**：评估本地小模型（如 3B、7B）作为写入/QA 模型的完整表现，以及不同判断模型间的一致性。
- **对抗性安全评估**：将 C5（对抗性）子集纳入主测试，评估系统对故意误导、混淆问题的抵抗力。
- **信念生命周期管理**：基于时间、事件（如用户修改证据）自动触发修订或失效，减少过时信念的影响。
- **多智能体协作**：研究 Eywa 架构在多智能体场景下共享记忆时的溯源、冲突解决与一致性维护。

## 10. 总结

Eywa 提出了一种以溯源为核心的长期记忆架构，通过将证据与信念彻底分离，实现了可审计、可诊断的记忆系统。其零 LLM 的读取路径和分层写入路径在设计上兼具高效性与透明性。虽然在实验覆盖、消融分析和超参稳定性方面存在不足，但该工作为 AI 智能体长期记忆领域确立了新的设计原则：记忆不应是提示工程的附庸，而应成为可追溯、可修正的基础设施。相关工件和代码的公开也为社区后续研究提供了坚实的复现基础。
