## 摘要
最近的大型语言模型（LLMs）在理解和生成代码方面展现出强大能力，涵盖从竞技编程到仓库级软件工程。在新兴的智能体系统中，代码不再仅仅是目标输出。它越来越多地作为智能体推理、行动、环境建模和基于执行的验证的操作基础。我们通过智能体框架的视角来阐述这一转变，并引入“代码作为智能体框架”：一种以代码作为智能体基础设施基础的统一视图。为了系统地研究这一视角，我们围绕三个相互关联的层面组织调查。首先，我们研究框架接口，其中代码将智能体连接到推理、行动和环境建模。其次，我们考察框架机制：用于长周期执行的规划、记忆和工具使用，以及使框架可靠且自适应的基于反馈的控制和优化。第三，我们讨论将框架从单智能体系统扩展到多智能体设置，其中共享的代码工件支持多智能体协调、审查和验证。在这些层面中，我们总结了代码作为智能体框架的代表性方法和实际应用，涵盖编码助手、GUI/OS自动化、具身智能体、科学发现、个性化和推荐、DevOps以及企业工作流。我们进一步概述了框架工程的开放挑战，包括超越最终任务成功的评估、不完整反馈下的验证、无回归的框架改进、跨多个智能体的一致共享状态、安全关键操作的人工监督以及多模态环境的扩展。通过将代码作为智能体AI的框架，本调查为可执行、可验证和有状态的AI智能体系统提供了统一的路线图。

## Abstract
Recent large language models (LLMs) have demonstrated strong capabilities in understanding and generating code, from competitive programming to repository-level software engineering. In emerging agentic systems, code is no longer only a target output. It increasingly serves as an operational substrate for agent reasoning, acting, environment modeling, and execution-based verification. We frame this shift through the lens of agent harnesses and introduce code as agent harness: a unified view that centers code as the basis for agent infrastructure. To systematically study this perspective, we organize the survey around three connected layers. First, we study the harness interface, where code connects agents to reasoning, action, and environment modeling. Second, we examine harness mechanisms: planning, memory, and tool use for long-horizon execution, together with feedback-driven control and optimization that make harness reliable and adaptive. Third, we discuss scaling the harness from single-agent systems to multi-agent settings, where shared code artifacts support multi-agent coordination, review, and verification. Across these layers, we summarize representative methods and practical applications of code as agent harness, spanning coding assistants, GUI/OS automation, embodied agents, scientific discovery, personalization and recommendation, DevOps, and enterprise workflows. We further outline open challenges for harness engineering, including evaluation beyond final task success, verification under incomplete feedback, regression-free harness improvement, consistent shared state across multiple agents, human oversight for safety-critical actions, and extensions to multimodal environments. By centering code as the harness of agentic AI, this survey provides a unified roadmap toward executable, verifiable, and stateful AI agent systems.

## 1. 论文的核心问题与整体含义（研究动机和背景）

*   **核心问题**：传统的视角将大语言模型生成的**代码视为最终产出物**（例如，程序或软件补丁）。然而，随着智能体系统的发展，代码的角色正在发生根本性转变。这篇论文的核心问题在于：**如何系统性地理解和构建一个以代码为中心的新范式，将代码作为智能体（Agent）进行推理、行动、验证和环境交互的基础操作平台（Harness）**？
*   **研究动机**：现有的智能体系统通常将代码生成、工具调用和环境反馈视为松散耦合的模块。这种割裂的设计导致系统在长周期任务中缺乏可靠性、可验证性和状态持久性。代码本身具有**可执行、可检查、有状态**的特性，使其成为连接模型推理与外部世界的理想媒介。然而，基于代码的智能体架构缺乏一个统一的理论视角和工程蓝图。
*   **整体含义**：论文提出了“**代码作为智能体框架**”这一统一视角。核心观点是：代码不仅是LLM的输出，更是智能体赖以生存的**操作基板（Operational Substrate）**。它将智能体的规划、记忆、工具使用、执行、反馈和验证等所有环节，都组织在可执行、可检查的代码周围。该视角旨在将智能体AI的可靠性问题，从依赖模型本身的推理能力，转移到构建可靠的系统级框架（Harness）上。

## 2. 论文提出的方法论：核心思想、关键技术细节

*   **核心思想**：论文并非提出单一算法，而是构建了一个**三层分析框架**来系统化地研究“代码作为智能体框架”这一概念。
    *   **第1层：框架接口**：研究代码如何作为智能体与外部世界交互的接口。
        *   **代码用于推理**：将中间计算外部化为可执行程序（如`Program-of-Thoughts`），利用执行结果验证推理步骤，解决纯语言推理的不稳定性。
        *   **代码用于行动**：将智能体的意图转化为可执行的策略，如机器人控制策略（`Code as Policies`）、GUI操作脚本或工具调用，并连接感知、规划和物理控制器。
        *   **代码用于环境建模**：将环境状态、动态和反馈信号表示为可执行的程序实体，如仓库状态、仿真器、测试用例和执行轨迹，使环境变得可检查和可操作。
    *   **第2层：框架机制**：研究支撑智能体稳定运行于长周期任务的核心机制。
        *   **规划**：通过线性分解、结构依赖图、搜索（如MCTS）或系统编排，将长期任务组织成可执行的步骤序列，控制智能体的执行轨迹。
        *   **记忆与上下文工程**：管理工作记忆、语义记忆（仓库证据）、经验性记忆、长期记忆和多智能体记忆，解决模型上下文窗口限制与任务状态不断增长的矛盾。
        *   **工具使用**：将智能体连接至API、仓库、沙箱、验证器等外部功能，并作为权限管理、结果处理和执行监控的治理接口。
        *   **框架控制与优化**：通过“**计划-执行-验证**”循环实现闭环控制。计划作为契约，执行在沙盒化环境中，验证通过确定性信号（测试、静态分析）完成，并引入人类审批和安全层。
    *   **第3层：扩展框架**：研究如何通过多智能体协作来扩展代码框架的规模。
        *   **角色专业化**：将规划、编码、测试、审查等角色分配给不同的智能体。
        *   **基于代码的交互模式**：智能体通过共享的代码工件（如仓库、测试结果、执行日志）进行协作、辩论和对抗性验证。
        *   **工作流拓扑**：从预定义的链式、循环式、分层式拓扑，迈向自适应的、由反馈驱动的动态拓扑。

*   **关键技术细节**：

    *   **`Code as Policies (CaP)`**：使用Python代码作为具身智能体的控制策略。
    *   **`Plan-Execute-Verify (PEV)`**：将调试过程重构为受控的状态机，明确区分每个环节的职责。
    *   **`Agentic Harness Engineering (AHE)`**：通过深度遥测（Deep Telemetry）和“进化智能体”来诊断、提出并验证对框架本身的修改，实现框架的自我优化。
