## 摘要
视觉语言模型正日益成为具身智能体的推理核心。机器人的执行本质上是迭代的：每个动作都会重塑场景和物理状态，不断更新需要感知、推理和验证的内容。满足这些需求需要功能互补的能力，而这些能力在监督信号、预测格式和验证标准上各不相同。现有方法通常针对孤立的、特定任务的目标来发展这些能力，而留下了如何围绕执行整体来组织和整合它们的问题。我们提出了Capek 0.5，一个围绕以执行为中心的能力分类法构建的具身视觉语言模型。该分类法不按数据集或任务来组织训练，而是根据具身能力在执行过程中的功能角色对其进行分组，包含四个能力族：空间推理、时间理解、动作引导和状态验证。每种能力首先由专门模型通过基于可验证奖励的强化学习从共享骨干中习得，然后通过权重空间合并以及随后的路由策略空间蒸馏，将各专门模型整合为单个推理时模型。我们在2B和35B-A3B两种规模上实例化了Capek 0.5，并从三个互补的角度进行评估：包括Capek-StateBench（一个用于状态验证的新基准）在内的综合基准套件；从专门模型到统一模型的能力保留受控研究；以及在模拟具身环境中的闭环评估。Capek 0.5在其初始化基础上改进了绝大多数匹配的基准行，在一个检查点中保留了所有四种专门能力并伴有量化损失，并且能够迁移到闭环具身任务执行中。

## Abstract
Vision-language models are increasingly serving as the reasoning core of embodied agents. Robot execution is inherently iterative: each action reshapes the scene and physical state, continually renewing what must be perceived, reasoned about, and verified. Meeting these demands requires complementary capabilities that differ in supervision signals, prediction formats, and verification criteria. Existing approaches typically develop these capabilities against isolated, task-specific objectives, leaving open how they should be organized and integrated around execution as a whole. We present Capek 0.5, an embodied vision-language model built around an execution-centric capability taxonomy. Rather than organizing training by datasets or tasks, the taxonomy groups embodied capabilities according to their functional roles throughout execution and comprises four capability families: Spatial Reasoning, Temporal Understanding, Action Guidance, and State Verification. Each capability is first acquired by a dedicated specialist through reinforcement learning with verifiable rewards from a shared backbone, and the specialists are then consolidated into a single inference-time model through weight-space merging followed by routed policy-space distillation. We instantiate Capek 0.5 at the 2B and 35B-A3B scales and evaluate it from three complementary perspectives: comprehensive benchmark suites including Capek-StateBench, a new benchmark for state verification; a controlled study of capability retention from specialists to the unified model; and closed-loop evaluation in simulated embodied environments. Capek 0.5 improves the large majority of matched benchmark rows over its initialization, retains all four specialized capabilities in one checkpoint with quantified losses, and transfers to closed-loop embodied task execution.

## 2. 论文提出的方法论

### 2.1 核心思想：执行中心能力分类法（Execution-Centric Capability Taxonomy）

将具身能力划分为四个能力族，每个族对应执行循环中的一类功能角色：

| 能力族 | 功能角色 | 输出格式 | 示例任务 |
|---|---|---|---|
| **空间推理（Spatial Reasoning）** | 理解场景几何与实体关系 | 关系、度量、多选答案 | 方向/方位、深度距离、跨视角对应 |
| **时间理解（Temporal Understanding）** | 建模事件进程与变化 | 时间区间 [t_start, t_end] | 事件排序、时间定位、因果推理 |
| **动作引导（Action Guidance）** | 将语言指令锚定到可执行视觉目标 | 2D点、边界框、有序轨迹 | 指代定位、可供性区域、轨迹预测 |
| **状态验证（State Verification）** | 验证物理谓词与任务完成度 | 是/否、状态标签、进度+下一步动作 | 物理状态验证、任务进度估计 |

### 2.2 两阶段训练范式：能力获取→能力整合

```
阶段一：能力专精化（Capability Specialization）
  共享骨干 Qwen3.6-35B-A3B / Qwen3.5-2B
      ↓ 各自能力对齐的数据 + 可验证奖励 + GRPO
  四个独立专家：空间专家、时间专家、引导专家、状态专家

  专家1 → ┐
  专家2 → ├→ TIES权重合并 → 统一学生初始化 → 路由MOPD蒸馏 → 单一推理模型
  专家3 → ┘
  专家4 → (权重空间)                    (策略空间)
```

### 2.3 关键技术与公式

**（1）Token级GRPO优化**
- 每个专家独立使用GRPO（Group Relative Policy Optimization）训练，无需学习价值函数。
- 组内相对优势：  
  \[
  \hat{A}_i = \frac{r_i - \bar{r}}{\sigma_r + \delta}
  \]
- Token级裁剪目标函数，包含重要性比率裁剪和KL正则化。

**（2）能力特化奖励设计**
- 统一奖励结构：格式奖励 + 任务准确性奖励，R = λ_fmt·R_fmt + λ_acc·R_acc。
- 各能力使用不同验证器：
  - **空间**：精确匹配、集合匹配、数值容差；
  - **时间**：时间IoU（tIoU），时空联合为 tIoU 与 box IoU 均值；
  - **引导**：点F1、目标掩码命中、对称最近邻得分，**轨迹用离散Fréchet距离（DFD）** 经指数核转换：R_traj = exp(-λ·D_DFD)，λ=10；
  - **状态**：精确匹配 + 进度截断邻近得分 r_value = max(0, 1−|p̂−p|/25)，组合奖励为 R = 0.5·r_value + 0.4·r_action + 0.1·r_fmt。

**（3）TIES权重合并初始化**
- 对每个专家的任务向量 Δ_e = θ_e − θ_0，TIES先修剪低幅值参数、选举坐标级共识符号、仅平均符号一致的更新：
  \[
  θ_{TIES} = θ_0 + λ·TIES_τ({Δ_e}_{e=1}^E), \quad τ=0.8, λ=1.0
  \]

**（4）路由MOPD（Multi-Teacher On-Policy Distillation）**
- 从TIES初始化出发，学生模型自行采样响应，按能力路由调用对应的冻结专家教师，在**学生生成的前缀**上做逐token反向KL蒸馏：
  \[
  L_{MOPD}(θ) = E[\frac{1}{|y|}\sum_t D_{KL}(π_θ(·|h_t)∥q_r(·|h_t))]
  \]
- 推理时仅需单一自回归检查点，路由机制只在训练时使用。
