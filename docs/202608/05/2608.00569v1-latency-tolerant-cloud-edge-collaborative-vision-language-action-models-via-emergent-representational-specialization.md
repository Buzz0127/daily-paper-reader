## 摘要
在移动机器人上部署数十亿参数的视觉-语言-动作（VLA）策略引发了一个系统冲突：语义推理受益于云GPU，而闭环控制必须在本地响应，尽管存在网络延迟和抖动。现有的分层和异步策略提高了吞吐量，但其慢路径表示仍可能过期到达，或需要显式调度和延迟提示。我们提出了CloudEdgeVLA，一种将时间错位视为表示学习问题的云边策略。云VLA将延迟观测编码为缓慢变化的任务特征，而轻量级边缘头将最新的可用云特征与当前本地视觉相结合。在训练期间，当前帧和随机延迟帧在新鲜路径和过期路径中与相同的当前动作目标配对。该目标鼓励云表示保留任务级信息，而边缘路径提供状态敏感的修正。在四个LIBERO套件中，CloudEdgeVLA在40步均匀延迟窗口内保持了63.8%–78.0%的成功率，而VLASH最多达到6.4%，所评估的单路径基线最多达到3.0%。通过从控制环路中移除阻塞同步，该设计为可扩展的VLA部署提供了一条实用途径，其中云模型可以增长，而边缘计算保持轻量和响应迅速。

## Abstract
Deploying billion-parameter Vision-Language-Action (VLA) policies on mobile robots creates a systems conflict: semantic reasoning benefits from cloud GPUs, whereas closed-loop control must respond locally despite network delay and jitter. Existing hierarchical and asynchronous policies improve throughput, but their slow-path representations can still arrive stale or require explicit scheduling and delay cues. We introduce CloudEdgeVLA, a cloud-edge policy that treats temporal misalignment as a representation-learning problem. A cloud VLA encodes delayed observations into slowly varying task features, while a lightweight edge head combines the latest available cloud feature with current local vision. During training, current and randomly delayed frames are paired with the same current action target in fresh and stale paths. This objective encourages the cloud representation to preserve task-level information while the edge path supplies state-sensitive corrections. Across four LIBERO suites, CloudEdgeVLA retains 63.8--78.0% success with a 40-step uniform-delay window, whereas VLASH reaches at most 6.4% and the evaluated single-path baselines at most 3.0%. By removing blocking synchronization from the control loop, the design offers a practical route to scalable VLA deployment in which cloud models can grow while edge computation remains lightweight and responsive.

## 论文总结

### 1. 核心问题与整体含义
- **背景冲突**：十亿参数级视觉-语言-动作（VLA）模型（如RT-2、OpenVLA、π0、Octo）在语义推理上表现优异，但其大规模计算需求难以部署在功耗和重量受限的移动机器人上；而机器人操控又需要低延迟的闭环控制。
- **云边协同的矛盾**：将计算卸载到云端会引入通信延迟、抖动和丢包，导致云端返回的特征描述的是"拍摄时的场景"，而非"动作执行时的场景"。若阻塞等待新特征则降低控制频率，若使用过期特征则产生时间错位。
- **现有方案不足**：多速率策略（MResT、DP-VLA、HiRT、SmolVLA）虽改善了吞吐量，但仍主要针对推理调度、动作块校正或显式时间条件化；动作块方法假设环境在开环执行期间静止；同步快慢流水线要求固定频率比和有限延迟，在真实网络条件下难以满足。
- **核心含义**：作者将时间错位重新定义为一个表示学习问题——通过"涌现表征特化"，让云端特征编码缓慢变化的任务信息（做什么），而边缘路径利用实时视觉提供状态敏感的控制修正（怎么做），从而让控制环路无需阻塞等待云端。

### 2. 方法论：核心思想、关键技术细节
- **核心架构**：CloudEdgeVLA由三个组件构成，具有清晰的时间不对称性：
  - **云端VLA骨干 fθ（System 2，延迟不敏感）**：基于预训练VLM的LoRA适配版本，处理观测o与指令ℓ，产生规划特征 h = fθ(o, ℓ) ∈ R^{L×D}（L = 动作块长度T × 动作维度A）。设计目标是编码"做什么"而非"何时做"。
  - **边缘视觉编码器 vψ（System 1 感知，延迟敏感）**：冻结的轻量级SigLIP-Base，从当前观测提取实时特征 z_t = vψ(o_t)，始终无延迟。
  - **边缘动作头 gϕ（System 1 控制，延迟敏感）**：将（可能过期的）云特征与实时视觉特征融合，输出动作块 â_t = gϕ(h_{t−k}, z_t)。具体做法：对规划特征在动作维度上做均值池化，将视觉特征投影到同一潜在空间，拼接后经残差MLP预测动作。
- **配对帧双路径训练（核心创新）**：
  - 从同一轨迹中取长度为W的观测窗口 W_t = {o_{t−W+1}, ..., o_t}，构造当前帧 o_t 和延迟帧 o_{t−d}（d ~ Uniform(1, W−1)）。
  - 两帧分别经云端骨干得到 h_fresh 和 h_stale（stale路径不回传阻断，两者都接收梯度）。
  - 两路特征都与同一实时视觉特征 z_t 融合，预测同一目标动作 a_t：
    - â_fresh = gϕ(h_fresh, z_t)，â_stale = gϕ(h_stale, z_t)
  - **双路径损失**：L = (1−λ)‖â_fresh − a_t‖₁ + λ‖â_stale − a_t‖₁
  - 使用课程学习：λ从0渐增至λ_max，让骨干先学强表征再被压制成延迟不变。
- **涌现表征特化机制**：过期路径的梯度 ∇θL_stale = ∇θ‖gϕ(fθ(o_{t−d}, ℓ), vψ(o_t)) − a_t‖₁ 中，跨随机d只有任务身份、目标、粗略进度等稳定信息能可靠预测a_t，而瞬时状态信息不可靠。这促使云端表示对时间位移不敏感（虽然不数学保证），边缘视觉特征则负责编码状态敏感信息。
- **部署协议**：边缘捕获观测→异步发送云端→云端返回时更新最新特征→边缘实时计算视觉特征→执行动作。**机器人永不阻塞等待云端**，始终使用最新收到的云特征与当前视觉。

### 6. 主要结论与发现
- **端到端延迟鲁棒性**：CloudEdgeVLA在d_max=40时对Spatial/Object/Goal/Long分别保持76.4/75.6/78.0/63.8%成功率，相对无延迟时仅下降18.5–27.9个百分点；最强基线VLASH同期最多6.4%，单路径基线最多3.0%。
- **综合指标**：四套件宏平均的归一化延迟AUC达90.8%（VLASH为32.4%）；同步成功保留率76.5%（VLASH仅1.8%）。
- **消融结论**：加入实时边缘视觉编码器带来63.5个百分点提升（31.6%→95.1%），说明"当前观测的直接路径"是鲁棒性的决定性因素；loss消融中仅stale supervision达89.2%，联合训练（fresh+stale）再增加5.9个百分点，说明延迟暴露与新鲜监督互补。
- **机制定位**：对比OpenVLA-OFT与训练后的CloudEdgeVLA，d=20时：骨干漂移D_h降低59.2%（0.391→0.160）、转移增益κ降低72.7%（1.082→0.295）、端到端动作漂移降低88.9%（0.423→0.047）、演示MAE降低88.5%（0.421→0.048）。鲁棒性来自"云端表示更稳定"与"动作头更好地衰减残余漂移"两方面的协同。
- **反事实审计的关键负结果**：在dh=20时，将边缘输入从同样过期改为当前，动作漂移仅从0.047104降至0.047097（edge-rescue fraction仅0.03%）。即这个检查点中，当前边缘视觉并没有直接大幅修复过期云特征，其优势主要来自更稳定的骨干和衰减型动作头。这一发现约束了机制主张，但不削弱端到端鲁棒性结论。
- **真实可行性**：RTT=1000ms时CE-VLA仍保持静态80%/动态70%成功率，VLASH降为0%。

### 7. 优点
- **概念清晰**：将System 1/System 2认知理论映射到云边推理架构，快慢系统各司其职，设计逻辑优雅。
- **接口简洁**：非阻塞式云边接口无需时钟或频率对齐，也不需要延迟元数据，实用性强。
- **训练方法巧妙**：配对帧双路径训练无需显式不变性损失或延迟条件标签，利用"同一动作目标同时监督新鲜与过期路径"自然地诱导时间特化；课程学习（λ渐进）缓解了训练稳定性问题。
- **证据链完整**：从闭环成功率到逐组件机制诊断（骨干/动作头分解、动作块维度分解、反事实审计），甚至包含一个直接测量边缘修正量大小的负结果——这种自我审计在机器人论文中罕见且宝贵。
- **公平比较**：统一的延迟网格、多随机种子报告，且诚实地指出了基线为点估计的局限。
- **清晰的部署路径**：让云模型规模和边缘计算解耦，具有实际工程价值。

### 8. 不足与局限
- **延迟分布泛化**：鲁棒性仅对测试的均匀延迟窗口成立；论文明确承认无法容忍无限延迟或云端断连（需要时间戳特征与本地回退策略）。
- **计算开销**：配对帧训练每次迭代需两次骨干前向传播，训练成本约为传统方案的两倍，论文未报告总训练预算。
- **感知模态受限**：冻结的RGB编码器可能丢失深度、力/触觉等对精细操作重要的信号。
- **真机验证薄弱**：单一平台、小样本（10次/格）、工作站级边缘设备，不足以证明嵌入式效率和广泛硬件泛化性。
- **机制主张需斟酌**：反事实审计显示当前边缘视觉的直接"救援"作用几乎为零（0.03%），说明论文标题所强调的"边缘实时视觉修正"在量化上弱于"骨干稳定化+头部衰减"效应。虽然作者诚实报告了这一结果，但它实际上削弱了"边缘视觉提供状态敏感修正"这一核心叙事。
- **未处理传输丢包**：只考虑了延迟，未明确应对网络丢包或乱序到达的场景。
- **新近度指标不足**：没有系统评估特征的最大可容忍年龄（如断连多少秒后必须切换到本地策略）。
- **泛化边界**：仅在LIBERO仿真+单一真实任务上测试，未涉及真实网络流量模式（如自相似延迟、突发拥塞）或多机器人并发场景。
